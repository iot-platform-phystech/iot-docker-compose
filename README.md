IoT Platform — Docker Compose

Описание

Данный каталог содержит конфигурацию Docker Compose для запуска инфраструктуры IoT-платформы.

В качестве системы хранения данных используется PostgreSQL. База данных предназначена для хранения пользователей, устройств и телеметрии, получаемой от датчиков.

Архитектура проекта

Платформа состоит из трёх основных компонентов:

HTTP Adapter — принимает HTTP-запросы от датчиков и передаёт их в IoT Core.

IoT Core — обрабатывает запросы, реализует бизнес-логику и взаимодействует с базой данных.

PostgreSQL — обеспечивает постоянное хранение данных платформы.

Данный каталог отвечает за запуск и настройку PostgreSQL.

Требования

Для запуска необходимы:

Docker Engine или Docker Desktop;

Docker Compose;

терминал с доступом к Docker.

Проверить установку можно командами:

docker --version
docker compose version

Структура каталога

iot-docker-compose/
├── docker-compose.yml
├── init.sql
└── README.md

Назначение файлов:

docker-compose.yml — конфигурация сервисов, портов, переменных окружения и постоянного хранилища.

init.sql — SQL-скрипт создания структуры базы данных при её первоначальной инициализации.

README.md — документация по настройке и запуску инфраструктуры.

Конфигурация базы данных

Текущая конфигурация разработки использует следующие параметры:

Параметр

Значение

Имя базы данных

iot_db

Пользователь

iot

Порт на хосте

5433

Порт внутри контейнера

5432

Имя контейнера

iot_postgres

Пароль должен совпадать со значением, указанным в docker-compose.yml и конфигурации IoT Core.

Если IoT Core запускается непосредственно в WSL, подключение выполняется через 127.0.0.1:5433.

Если IoT Core запускается в Docker в той же сети, что и PostgreSQL, необходимо использовать имя сервиса базы данных и порт 5432.

Указанные параметры предназначены для локальной разработки. Для production-среды следует использовать безопасное управление секретами и паролями.

Запуск PostgreSQL

Перейдите в каталог проекта:

cd /bred/IoT/iot-docker-compose

Запустите базу данных в фоновом режиме:

docker compose up -d

Проверьте состояние контейнеров:

docker compose ps

Просмотрите логи PostgreSQL:

docker compose logs -f db

Если сервис базы данных в docker-compose.yml называется иначе, укажите его фактическое имя вместо db.

Инициализация базы данных

Файл init.sql определяет структуру базы данных и создаёт три основные таблицы.

Таблица devices

Хранит зарегистрированные устройства:

UUID устройства;

имя;

серийный идентификатор;

идентификаторы правил;

дополнительные метаданные.

Таблица users

Хранит данные пользователей:

UUID пользователя;

имя;

адрес электронной почты;

хеш пароля;

список связанных устройств;

настройки уведомлений.

Таблица telemetry

Хранит измерения, полученные от устройств:

UUID записи;

UUID устройства;

данные измерения в формате JSONB;

временную метку.

Таблица telemetry связана с таблицей devices посредством внешнего ключа device_id.

Для идентификаторов используется тип UUID, а для хранения структурированных данных — JSONB.

Важно: PostgreSQL выполняет скрипты из каталога /docker-entrypoint-initdb.d/ только при первоначальном создании базы данных с пустым каталогом данных. Изменение init.sql не приводит к автоматическому обновлению уже созданных таблиц.

Изменения существующей схемы необходимо применять отдельно через psql или систему миграций.

Подключение к PostgreSQL

Откройте консоль PostgreSQL внутри контейнера:

docker exec -it iot_postgres psql -U iot -d iot_db

Посмотрите список таблиц:

\dt

Посмотрите структуру таблиц:

\d devices
\d users
\d telemetry

Получите список зарегистрированных устройств:

SELECT id, name, serial_id
FROM devices;

Получите последние измерения:

SELECT id, device_id, data, time
FROM telemetry
ORDER BY time DESC
LIMIT 10;

Для выхода из консоли:

\q

Постоянное хранение данных

Для хранения данных PostgreSQL используется Docker volume. Благодаря этому данные сохраняются при перезапуске контейнера.

Посмотреть список томов:

docker volume ls

Остановить контейнеры:

docker compose down

Повторно запустить сервисы:

docker compose up -d

При обычной остановке и повторном запуске существующий том используется повторно, поэтому записи базы данных сохраняются.

Внимание: команда docker compose down -v удаляет связанные с проектом тома и может привести к потере данных. Не используйте её, если требуется сохранить существующую базу.

Проверка работоспособности

После запуска PostgreSQL проверьте, что контейнер работает:

docker compose ps

Проверьте возможность подключения к базе:

docker exec -it iot_postgres \
    psql -U iot -d iot_db -c "SELECT NOW();"

Если команда возвращает текущее время базы данных, PostgreSQL доступен для выполнения запросов.

Остановка

Остановить контейнеры без удаления данных:

docker compose down

Повторный запуск выполняется командой:

docker compose up -d
